# Native build steps

Updated: 5 October 2026.

The Xcode project uses a local Swift package. It uses relative paths from this checkout. It does not use a saved DerivedData folder.

## Prepare resources

The project reads app and widget files from `build/native-evidence/L03/staged/run-10`. Build outputs stay outside Git. On a clean checkout, run these commands from the repository root:

```sh
python3 scripts/native/resources/stage-resources.py build/native-evidence/L03/staged/run-9
python3 scripts/native/resources/stage-resources.py build/native-evidence/L03/staged/run-10
python3 scripts/native/resources/verify-staging.py build/native-evidence/L03/staged/run-9 build/native-evidence/L03/staged/run-10
```

Use both runs to check that the generated bytes match. Do not edit staged files. Change source resources and run the staging steps again in a clean output directory when resource inputs change.

## Build the development app

Use the `John Development` scheme for simulator work. This scheme uses the development app group and the bundle ID `com.nrsv.verse.dev`. Keep the signed update scheme and release bundle ID for the same-ID acceptance checks.

```sh
xcodebuild -project native/John/John.xcodeproj \
  -scheme 'John Development' \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' \
  -derivedDataPath build/native-evidence/L02/DerivedData \
  ONLY_ACTIVE_ARCH=YES CODE_SIGNING_ALLOWED=NO build
```

The staged app folder remains `App` in the app bundle. The staged widget folder remains `Widget` in the extension bundle. App fonts use these subfolder paths in `UIAppFonts`.

## Continuous integration

`.github/workflows/native-simulator.yml` checks Xcode 26.6 (17F113), checks for an iPhone 17 Pro on iOS 26.5 through the simulator JSON list, stages resources twice at the project paths, and checks equal output. It then runs the UI test on the selected simulator. It uses Bun 1.3.14 from `bun.lock`. The workflow runs for pull requests and manual requests. It saves the Xcode result bundle as an artifact.
